# 多 Agent 协作入门

本课讲的是「什么时候该把一个任务拆给多个 Agent 去做，以及怎么拆」。你会学到编排者-子代理（orchestrator-worker）架构、如何写出子代理能独立理解的委派提示词、流水线/评审/投票几种常见协作模式各自的适用场景，以及多 Agent 系统特有的失败模式——子代理声称「完成了」不能直接采信，必须自己复核。适合已完成本系列前 5 门课、会写基础提示词、懂工具调用协议、还没系统了解过多 Agent 分工协作的开发者。本课不讲多 Agent 系统的底层框架源码、不讲分布式系统里的共识算法，也不会教你从零搭一个通用的 Agent 编排平台；第 6 课会用 Claude API 写一个可运行的双 Agent（生产者-评审者）流水线作为落地练习，但目标是让你理解协作模式本身，而不是产出一个可以直接上生产的框架。

## 学习目标

- 判断一个任务是否值得拆成多个 Agent，识别「协调开销大于收益」的场景
- 说明编排者-子代理架构里上下文隔离的价值，以及为什么子代理只应该回传结论
- 给子代理写出自包含、有明确范围和输出格式要求的委派提示词
- 区分流水线、生产者-评审者、多视角投票三种协作模式，并判断各自的适用场景
- 识别多 Agent 协作里的典型失败——子代理自称完成不可信、重复劳动、结果冲突——并知道如何应对
- 用 Claude API 写一个可运行的生产者-评审者双 Agent 流水线

## 前置要求

- 已完成本系列前 5 门课，会写基础提示词、理解工具调用协议、了解 Agent 记忆与状态、能读懂基础 JavaScript
- 有 Node.js 运行环境，能在终端里执行脚本
- 有可用的 Claude API key（第 6 课的动手练习需要）
