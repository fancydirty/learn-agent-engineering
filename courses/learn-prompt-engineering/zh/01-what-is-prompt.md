## 你已经在用 prompt，但可能用得不够好

当你打开 ChatGPT 或 Claude，在输入框输入"帮我写一份报告"，然后得到一份泛泛而谈、跟你实际需求对不上的内容——这不是 AI 的问题，而是你的 prompt 太模糊了。AI 看到的只是五个字，它不知道报告是给谁看的、要解决什么问题、应该用什么语气、包含哪些内容。

Prompt 就是你给 AI 的指令[^S13]。它决定了 AI 能理解多少你的意图，以及输出质量的上限。同样的问题，模糊指令得到泛泛的答案，清晰指令得到精准的结果。本课教你识别两者的差别，为后续学习打基础。

## 什么是 Prompt

**Prompt**（提示词、指令）是你输入给大语言模型（LLM）的文本，用来告诉它你想要什么[^S13]。可以是一个问题、一段描述、一个任务要求，或者这些的组合。

大语言模型（LLM）是一种 AI 系统，通过学习海量文本训练出来，能够理解自然语言并生成回答[^S14]。ChatGPT、Claude、文心一言都属于这一类。它们不是搜索引擎——不是去网上找现成答案，而是根据训练时学到的模式，生成一段新的、符合你指令的文本。

关键在于：**LLM 只能根据你的 prompt 来理解任务**。你没说的信息，它只能猜；你说得越清楚，它的输出就越符合预期。

## 对比：模糊 prompt vs 清晰 prompt

看两个真实例子的差异。

**场景 1：请 AI 解释一个技术概念**

❌ **模糊 prompt**：
```
什么是 API
```

AI 可能给你：
- 一段教科书式的定义（"API 是应用程序编程接口的缩写……"）
- 过于技术化的解释（假设你懂编程）
- 或者太浅显（只说"让程序之间交流"）

✅ **清晰 prompt**：
```
我是产品经理，不懂编程。请用日常生活的例子解释什么是 API，
让我能跟开发团队讨论需求时听懂他们在说什么。
```

AI 会给你：
- 贴近产品经理视角的解释
- 日常生活类比（比如"餐厅的菜单就是一种 API"）
- 跟实际工作场景相关的例子

差别在哪？清晰 prompt 明确了三件事：**你是谁（产品经理）、你的背景（不懂编程）、你要用这个知识做什么（跟开发讨论需求）**。

**场景 2：请 AI 写一段代码**

❌ **模糊 prompt**：
```
写一个 Python 函数处理数据
```

AI 只能瞎猜：
- 什么数据？列表、字典、文件、数据库？
- 怎么处理？排序、过滤、转换、统计？
- 输入输出是什么格式？

✅ **清晰 prompt**：
```
写一个 Python 函数，输入是包含用户评分的列表（1-5分），
过滤掉低于3分的评分，返回剩余评分的平均值，保留一位小数。
包含类型注解和文档字符串。
```

AI 能给出：
- 明确的函数签名
- 符合要求的过滤和计算逻辑
- 清晰的文档和类型标注

差别在哪？清晰 prompt 指明了**输入格式、处理逻辑、输出要求、代码风格**。

## Prompt 质量决定输出质量

研究表明，在复杂任务上，写清楚 prompt 能让 AI 完成任务的效率提升 11 倍以上[^S7]。但反过来，模糊的 prompt 会导致：

- **来回修改次数增加**：你得到一个不符合预期的回答，补充说明，再得到一个偏了的回答，再补充……多次往返才能接近你要的结果
- **输出不一致**：同样的模糊问题，每次得到的答案风格、详细程度、侧重点都不同
- **浪费 token 和时间**：模糊 prompt 让 AI 生成一堆你用不上的内容，消耗 token 配额（如果你用的是付费 API）或等待时间

**关键发现**：微软开发者工具研究组发现，在代码生成任务中，明确写清需求细节的 prompt 能减少 68% 的来回修改[^S12]。这意味着你第一次就更可能拿到能用的代码，而不是在第三、四轮对话后才接近目标。

清晰 prompt 的回报是立竿见影的：更少的试错、更高的首次成功率、更可控的输出。

## Prompt 工程是一项技能

Prompt 工程（Prompt Engineering）是设计、优化 prompt 的系统化方法[^S13]。它不是"找到一个魔法咒语"，而是理解 AI 的工作方式，学会用它听得懂的方式表达需求。

2026 年的现状是：AI 模型的指令遵循能力已经很强，能理解复杂指令、处理长文本、完成多步骤任务[^S6]。但它们仍然依赖你的 prompt 来确定任务边界。模型不会读心——你不说，它就不知道。

Prompt 工程包括：
- 写清楚指令的基本结构（第 02 课）
- 用示例引导 AI 理解模式（第 03 课）
- 让 AI 展示推理过程（第 04 课）
- 系统化地调试和改进（第 05 课）
- 针对不同任务选择策略（第 06 课）

这门课程教的是可复用的方法，不是一次性的技巧。掌握这些方法后，你能更高效地使用任何大语言模型工具。

## 小结

Prompt 是你给 AI 的指令，决定了 AI 能理解多少你的意图。模糊的 prompt 让 AI 猜测，清晰的 prompt 明确任务边界、输出格式和背景信息。研究显示，清晰的 prompt 能显著减少来回修改次数、提升任务完成效率。

### Level 1：识别和改写模糊 prompt

你的同事写了一个 prompt："帮我优化这段代码"。请指出这个 prompt 的三个主要问题，并改写为一个清晰的版本。

<!-- rubric -->
- 识别出至少 2 个关键问题（缺少优化目标、未说明代码语言或上下文、没有指定输出格式）
- 改写后的 prompt 明确了优化目标（性能/可读性/安全性等）
- 改写后的 prompt 包含了必要的上下文信息
- 改写后的 prompt 指定了期望的输出格式
<!-- answer -->
**问题分析**：
1. 未说明优化目标：是性能、可读性、还是安全性？
2. 缺少代码上下文：什么语言？做什么的？有什么已知问题？
3. 没有输出格式：是要修改后的代码、还是优化建议列表？

**改写示例**：
```
你是一位资深的 Python 性能优化工程师。

请分析下面这段 Python 数据处理代码的性能瓶颈，并给出优化建议。

代码背景：这段代码用于处理包含 10 万条用户记录的列表，当前运行需要 30 秒。

输出格式：
1. 当前性能瓶颈（按影响从大到小排序，说明在什么数据量下会成为问题）
2. 优化建议（每条包含：具体修改点、预期性能提升、优化后的代码片段）

代码：
[粘贴代码]
```

<!-- hint -->
从第 02 课学到的四要素入手：这个 prompt 缺少哪些要素？角色、任务、格式、约束各有什么问题？
<!-- hint -->
想一想：如果你是 AI，看到"优化代码"这四个字，你能确定要做什么吗？你需要什么额外信息才能给出有用的建议？

### Level 2：为真实场景设计 prompt

选择你最近使用 AI 工具时遇到的一个场景（或使用以下场景）：**让 AI 帮你写一封给客户的邮件，说明产品延期交付的原因并致歉**。

设计一个清晰的 prompt，确保 AI 能生成符合你需求的邮件。

<!-- rubric -->
- Prompt 明确了邮件的目标受众（客户的身份和背景）
- Prompt 说明了延期的具体原因和新的交付时间
- Prompt 指定了邮件的语气和风格（正式、诚恳、专业等）
- Prompt 包含了必要的约束（长度、结构、避免的内容等）
- Prompt 的结构清晰，AI 能一次理解所有要求
<!-- answer -->
**示例 prompt**：

```
你是一位专业的客户关系经理，擅长在困难情况下维护客户信任。

请帮我写一封给企业客户的邮件，说明软件项目延期交付的情况。

背景信息：
- 客户：某银行的 IT 部门主管
- 项目：为其开发的风险管理系统
- 原定交付时间：2024-03-15
- 新交付时间：2024-04-01（延期 2 周）
- 延期原因：安全审计发现需要加强数据加密模块，这是确保系统安全性的必要改进

邮件要求：
- 语气：正式、专业、诚恳
- 结构：致歉 → 说明原因 → 强调价值（为什么这个延期对客户有利）→ 新时间表 → 补偿措施
- 长度：不超过 300 字
- 避免：过度道歉（不要连续多次说"非常抱歉"）、推卸责任、空洞的保证

输出：
只输出邮件正文，不要输出"邮件内容如下"之类的引导语。
```

**为什么这个 prompt 有效**：
- 明确了角色（客户关系经理）和写作场景
- 提供了所有必要的背景信息（who、what、when、why）
- 指定了语气、结构、长度等具体要求
- 明确了要避免的内容，防止 AI 犯常见错误
- 清晰的输出格式要求，便于直接使用

<!-- hint -->
先列出这封邮件必须包含的关键信息：谁、什么事、为什么、新的时间表、如何弥补。然后思考：如何让 AI 在理解这些信息的同时，掌握合适的语气和风格？
<!-- hint -->
如果你第一次写的 prompt 不够清晰，先自己试一次，看 AI 的输出哪里不符合预期，然后针对性地补充约束条件。记住：调试 prompt 是正常的迭代过程。
