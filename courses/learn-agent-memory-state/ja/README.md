# エージェントメモリと状態

エージェントは 10 分前に議論したことを「覚えている」ように見えますが、そのメモリは実際にはモデルの頭の中に存在しません――単にすべてのリクエストのコンテキストウィンドウに逐語的に詰め込まれているだけです。このコースはその幻想を解体します。なぜコンテキストウィンドウがエージェントのすべてのメモリに等しいのか、なぜ会話履歴は増え続けるだけなのか、いつメモリをファイルに書き込むべきか、エージェントがタスクの状態をどのように記憶するか、そしてメモリ自体が導入するセキュリティリスクは何かを学びます。このシリーズの最初の 4 つのコースを終え、エージェントにセッションをまたいで情報を記憶させたい開発者向けです。コンテキストウィンドウからファイルレベルの永続的メモリまでのチェーンに焦点を当てており、ベクトルデータベースや RAG 取得システムの構築、モデルレベルでのメモリトレーニングはカバーしません。最後には、読み書き可能で圧縮可能な永続的メモリレイヤーを自分でエージェントに配線します。

## 学習目標

このコースを終えると、次のことができるようになります:

- 「エージェントがメモリを持っている」が幻想である理由を説明し、コンテキストウィンドウが実際に何を保持しているかを正確に述べる
- 大きくなりすぎた会話履歴に対する 3 つの戦略を挙げ、それぞれが何を削除し何を保持するかを判断する
- ファイルベースの外部メモリスキームを設計し、何を書き込み、いつそれを取得するかを知る
- 構造化された状態（タスクリスト、チェックポイント）を使用して、エージェントが最初からやり直すのではなく中断から再開できるようにする
- メモリポイズニングの攻撃経路を認識し、少なくとも 2 つのターゲット防御策を挙げる
- 読み書きツールと圧縮ロジックを自分でエージェントに配線し、実行可能な永続的メモリレイヤーを構築する

## 前提知識

- このシリーズの最初の 4 つのコースを完了し、構造化されたプロンプトを書くことができる
- ツール呼び出しラウンドトリッププロトコル（tool_use / tool_result）を理解している
- 基本的な JavaScript（変数、関数、async/await、配列メソッド）を読むことができる
- Node.js スクリプトを実行できるローカル環境がある
