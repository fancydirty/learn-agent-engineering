# 第 3 课：动手实践：编写你的第一个 Skill

> 学习目标：
> - 创建 Skill 的目录结构
> - 从零编写一个完整的 SKILL.md
> - 理解渐进式披露原则
> - 第一次调用你的 Skill
>
> 前置要求：[<< 第 2 课](./02-skill-anatomy.md) | 下一课 [第 4 课 >>](./04-testing-debugging.md)

## 我们要做什么

这一课，我们从零开始创建一个真实可用的 Skill：**任务整理器**。

**它做什么：**
- 输入：一堆混乱的待办事项（文字、截图里的文字、会议记录）
- 输出：按优先级和截止日期整理好的清单

**为什么选这个：**
- 简单，不涉及复杂逻辑
- 实用，你马上就能用上
- 展示了 Skill 的核心结构

## 第 1 步：创建目录和文件

打开终端，执行：

```bash
# 创建 personal skills 目录（如果还没有）
mkdir -p ~/.claude/skills

# 创建 Skill 目录
mkdir ~/.claude/skills/task-organizer

# 创建 SKILL.md 文件
touch ~/.claude/skills/task-organizer/SKILL.md
```

**目录结构现在是这样：**

```
~/.claude/skills/
└── task-organizer/
    └── SKILL.md
```

用你的文本编辑器（VS Code、Cursor、或其他）打开 `SKILL.md`。

## 第 2 步：写 frontmatter

先写文件开头的元数据：[^S1]

```markdown
---
name: task-organizer
description: 整理待办事项，按优先级和截止日期分组。用于处理混乱的任务列表、会议行动项或项目待办
---
```

**检查清单：**
- ✓ `name` 是小写、用连字符
- ✓ `description` 说了做什么（整理待办）、输入是什么（混乱列表）、什么时候用（会议行动项、项目待办）

## 第 3 步：写标题和简介

frontmatter 之后，加上标题：

```markdown
# 任务整理器

从混乱的文本中提取任务，按优先级和截止日期整理成结构化清单。
```

**为什么要写标题和简介：**
- 标题给人看（如果你过几个月回来看这个文件，能快速想起它是干什么的）
- 简介给 Claude 看（补充 description 没说清楚的细节）

## 第 4 步：定义输入格式

告诉 Claude 接受什么样的输入：[^S5]

```markdown
## 输入格式

接受以下任何格式的任务列表：

- 纯文本列表（每行一个任务）
- Markdown checklist（`- [ ] 任务内容`）
- 带时间标记的消息（"明天之前要完成 X"）
- 会议记录中的行动项

**示例输入：**

```
完成季度报告
- [ ] 审查 PR #234
明天要修复那个登录 bug
周五之前准备演示 demo
更新文档
```
```

**这里做了什么：**
- 列出了所有可能的输入格式
- 给了一个示例，让 Claude 看到真实的输入长什么样

## 第 5 步：写处理步骤

这是 instructions 的核心部分，要写得足够具体：[^S5]

```markdown
## 处理步骤

按顺序执行以下步骤：

1. **提取任务**
   - 每行或每个列表项是一个任务
   - 移除勾选框标记（`- [ ]` 或 `- [x]`）
   - 保留任务的核心描述

2. **识别时间信息**
   - 查找日期关键词：今天、明天、本周、周X、具体日期（2024-01-15）
   - 查找时间表达：XX 之前、截止 XX、XX 前完成
   - 如果没有明确时间，标记为"无明确截止"

3. **判断优先级**
   - 包含"紧急""ASAP""尽快""立即"→ 紧急
   - 包含"重要""优先""关键"→ 重要
   - 今天或明天到期 → 紧急
   - 本周内到期 → 重要
   - 其他 → 普通

4. **排序**
   - 同一优先级内，按截止日期排序，最近的在前
   - 无明确截止日期的排在该优先级最后
```

**为什么要这么详细：**

Claude 不是人，不会"理解你的意思"。你写"判断优先级"，它不知道按什么标准判断。但你写"包含'紧急'→ 紧急"，它就知道该怎么做。[^S2]

## 第 6 步：定义输出格式

告诉 Claude 结果应该长什么样：

```markdown
## 输出格式

按以下结构输出，使用 emoji 作为优先级标识：

### 🔴 紧急（今天或明天）
- [任务内容] - 截止时间

### 🟡 重要（本周）
- [任务内容] - 截止时间

### ⚪ 普通
- [任务内容] - 截止时间（如果有）

**示例输出：**

### 🔴 紧急
- 修复登录 bug - 明天
- 完成季度报告 - 今天

### 🟡 重要
- 审查 PR #234 - 周五
- 准备演示 demo - 周五

### ⚪ 普通
- 更新文档 - 无明确截止
```

**给示例的好处：**

Claude 看到示例，就知道具体的排版、符号、格式。不用猜"emoji 放哪里""时间写在前面还是后面"。

## 第 7 步：处理边界情况

补充特殊情况的处理方式：

```markdown
## 注意事项

- 如果输入是空的或没有识别到任何任务，输出"未识别到有效任务"
- 如果所有任务都没有时间信息，全部归为"普通"类别
- 如果任务描述太长（超过 100 字），保留前 80 字 + "..."
- 已完成的任务（标记为 `[x]`）忽略不处理
```

## 完整文件

现在，你的 `SKILL.md` 应该是这样的：

```markdown
---
name: task-organizer
description: 整理待办事项，按优先级和截止日期分组。用于处理混乱的任务列表、会议行动项或项目待办

从混乱的文本中提取任务，按优先级和截止日期整理成结构化清单。

## 输入格式

接受以下任何格式的任务列表：

- 纯文本列表（每行一个任务）
- Markdown checklist（`- [ ] 任务内容`）
- 带时间标记的消息（"明天之前要完成 X"）
- 会议记录中的行动项

## 处理步骤

按顺序执行以下步骤：

1. **提取任务**
   - 每行或每个列表项是一个任务
   - 移除勾选框标记
   - 保留任务的核心描述

2. **识别时间信息**
   - 查找日期关键词：今天、明天、本周、周X、具体日期
   - 查找时间表达：XX 之前、截止 XX
   - 如果没有明确时间，标记为"无明确截止"

3. **判断优先级**
   - 包含"紧急""ASAP""尽快"或今天/明天到期 → 紧急
   - 包含"重要""优先"或本周内到期 → 重要
   - 其他 → 普通

4. **排序**
   - 同一优先级内，按截止日期排序，最近的在前

## 输出格式

### 🔴 紧急（今天或明天）
- [任务内容] - 截止时间

### 🟡 重要（本周）
- [任务内容] - 截止时间

### ⚪ 普通
- [任务内容] - 截止时间（如果有）

## 注意事项

- 如果输入是空的，输出"未识别到有效任务"
- 如果所有任务都没有时间信息，全部归为"普通"
- 任务描述太长（超过 100 字）时，保留前 80 字 + "..."
- 已完成的任务（`[x]`）忽略不处理
```

保存文件。

## 第 8 步：第一次调用

打开 Claude Code，输入：

```
/task-organizer

完成季度报告
审查 PR #234，周五之前
明天修复登录 bug
更新文档
紧急：客户反馈的支付问题
```

Claude 应该输出：

```
### 🔴 紧急
- 修复登录 bug - 明天
- 客户反馈的支付问题 - 无明确截止

### 🟡 重要
- 审查 PR #234 - 周五

### ⚪ 普通
- 完成季度报告 - 无明确截止
- 更新文档 - 无明确截止
```

**如果输出不对，不要慌。** 下一课我们专门讲调试。

## 渐进式披露：为什么不一次写完所有细节

你可能注意到，这个 Skill 没有处理"任务有依赖关系"或"任务分配给不同的人"。[^S2][^S5]

**这是故意的。**

**渐进式披露原则：只给 Claude 它当前需要的信息，不要一次性塞太多。**[^S2]

第一个版本只做最核心的功能：提取、分类、排序。等你用了几天，发现确实需要"任务分配"功能，再加进去。

**好处：**
- Skill 文件短，Claude 加载快
- 逻辑简单，不容易出错
- 你能快速验证核心功能是否正常

等第一个版本跑通了，再迭代。这是所有好的 Skill 的开发方式。[^S2]

## 💻 练习

### Level 1：创建你自己的第一个 Skill

用第 1 课和第 2 课练习中确定的任务，创建一个完整的 SKILL.md。

**要求：**
1. 创建目录结构
2. 写完整的 frontmatter（name + description）
3. 写 instructions，至少包含：输入格式、处理步骤、输出格式
4. 保存文件
5. 在 Claude Code 里调用一次

<!-- rubric -->
- 目录结构正确（`~/.claude/skills/你的skill名/SKILL.md`）
- frontmatter 的 name 和 description 符合规范
- instructions 包含了输入、步骤、输出三个部分
- 步骤写得足够具体（不是"分析数据"这种泛化描述）
- 成功调用了一次，不管结果对不对

<!-- answer -->
示例（基于客户反馈分类任务）：

```markdown
---
name: feedback-classifier
description: 整理 Slack 客户反馈，分类为 bug 报告、功能请求、使用疑问，并标注优先级。用于每日反馈汇总
---

# 客户反馈分类器

从 Slack 消息中提取客户反馈，按类型和优先级整理。

## 输入格式

接受以下格式：
- Slack 消息导出（纯文本）
- 客户反馈截图的文字识别结果
- 手动复制粘贴的消息

## 处理步骤

1. **提取反馈内容**
   - 识别每条消息的核心问题或请求
   - 移除无关的聊天内容（问候、感谢等）

2. **判断类型**
   - 描述了错误、崩溃、功能不正常 → Bug 报告
   - 希望增加某个功能、改进体验 → 功能请求
   - 询问如何使用、为什么这样 → 使用疑问

3. **标注优先级**
   - 影响生产环境、导致无法使用 → P0（最高）
   - 影响部分用户、有替代方案 → P1
   - 体验优化、锦上添花 → P2

4. **提取关键信息**
   - 涉及的功能模块
   - 用户身份（如果提到）
   - 时间敏感性

## 输出格式

### Bug 报告
- [问题描述] - 优先级 - 模块

### 功能请求
- [请求内容] - 优先级 - 模块

### 使用疑问
- [问题] - 模块

## 注意事项

- 如果一条消息同时包含多个问题，拆分成多条
- 如果无法判断优先级，标记为 P1
- 保留原始消息的时间戳（如果有）
```

不确定步骤写得够不够具体？问自己：如果让一个从没做过这个任务的同事照着这个文件做，他能做对吗？

第一个版本不需要完美。先写核心流程，能跑起来就行。细节可以后面迭代

## 小结

- **创建 Skill 的 7 个步骤**：目录→frontmatter→标题→输入→步骤→输出→边界情况
- **步骤要具体**：不能写"分析任务"，要写"查找日期关键词：今天、明天..."
- **给示例很重要**：让 Claude 看到输入和输出的实际样子
- **渐进式披露原则**：第一个版本只做核心功能，不要一次写完所有细节
- **调用方式**：`/skill-name` + 输入内容
