## 你每次都在重复解释同一个流程

你正在用 Claude Code 整理会议记录。你说："帮我把这段会议录音转成结构化的要点，分成决策、行动项和待讨论三部分，每个行动项要标注负责人和截止日期。"

Claude 完成了。效果很好。

第二天，另一个会议。你又说了一遍同样的话。

第三天，第四天……每次开会后，你都在重复同样的指令。Claude 每次都能做好，但你每次都得重新解释。[^S1]

**这就是 Skills 要解决的问题**：把你反复解释的工作流程，打包成一个可复用的指令。一次编写，随时调用。[^S2]

## 什么是 Skill

**Skill 是一个目录，里面有一个 SKILL.md 文件，告诉 Claude 如何完成某个特定任务。**[^S3]

它像是给 Claude 准备的作业指导书。你把步骤写清楚，Claude 看着做。不需要每次都从头解释。[^S4]

举个例子，会议记录整理 Skill 的核心内容可能是：

```markdown
---
name: meeting-notes
description: 整理会议录音或文字稿，提取决策、行动项和待讨论内容
---

# 会议记录整理

## 步骤

1. 读取会议内容（文字稿或录音文件）
2. 提取所有明确的决策，每条一行
3. 提取所有行动项，格式：[行动] - 负责人 - 截止日期
4. 列出所有被提及但未决定的待讨论事项
5. 按时间顺序输出，最近的截止日期排在前面
```

保存后，你只需要输入 `/meeting-notes` 加上会议内容，Claude 就知道该怎么做。[^S1]

## Skills 适合什么场景

**适合 Skills 的场景有三个特征：**

1. **重复性**：你每周、每天、甚至每小时都在做同样的事
2. **步骤固定**：流程可以写成清晰的步骤，不是每次都不一样
3. **可以验证**：你能判断 Claude 做得对不对

**典型场景：**

- 代码审查（检查是否遵循团队规范）
- 文档格式转换（Markdown 转 Word，保留特定格式）
- 日志分析（从错误日志中提取关键信息）
- 测试用例生成（根据功能描述生成测试场景）
- 提交信息规范化（将简略的 commit 改写成团队约定的格式）

**不适合 Skills 的场景：**

- 一次性任务（比如"帮我设计这个页面的布局"）
- 每次都需要大量人工判断的任务
- 完全开放式的创意工作

## Skills 如何工作

当你创建一个 Skill，你实际上是在做两件事：[^S5]

1. **写一个 YAML frontmatter**（文件开头用 `---` 包裹的部分），告诉 Claude「这个 Skill 叫什么名字、什么时候用它」
2. **写 Markdown 指令**（frontmatter 后面的正文），告诉 Claude「拿到任务后具体怎么做」

**两种使用方式：**

- **手动调用**：你输入 `/meeting-notes`，Claude 加载这个 Skill 的指令，然后执行
- **自动触发**：你说"帮我整理这段会议记录"，Claude 看 description 觉得 meeting-notes 这个 Skill 相关，就自动加载它[^S6]

自动触发的前提是 description 写得好。这个我们第 2 课详细讲。

## Skill 存在哪里

**两个位置：**[^S1]

- **Personal skills**：`~/.claude/skills/` - 你自己用的，所有项目都能访问
- **Project skills**：`.claude/skills/` - 放在项目目录里，团队成员克隆代码后也能用

第一次创建 Skill，从 personal skills 开始。等你写了几个、确认有用了，再考虑把常用的放进项目目录，让团队一起用。

## 💻 练习

### Level 1：识别你的第一个 Skill 候选

回顾你最近一周的工作，找到一个你向 Claude 重复解释过至少 3 次的任务。

写下来：
1. 这个任务是什么？
2. 它的步骤是否固定？
3. 你能判断 Claude 做得对不对吗？

<!-- rubric -->
- 任务描述清晰，能让别人理解你在做什么
- 明确说明了步骤是否固定
- 说明了如何验证结果

<!-- answer -->
示例答案：

**任务**：整理 Slack 频道里的客户反馈，分成 bug 报告、功能请求、使用疑问三类

**步骤固定吗**：是。每次都是读消息、判断类型、归类、加上优先级标签

**能验证吗**：能。我能看分类对不对，优先级标不标得合理

**是否适合 Skill**：适合。重复性高、步骤固定、可验证

<!-- hint -->
如果想不出来，可以从这些方向找：你每天/每周做的、你给 Claude 的指令超过 3 句话的、你希望团队其他人也能用同样方式做的

<!-- hint -->
不需要是编程任务。文档整理、数据清洗、格式转换、内容审核，都可以

## 小结

- **Skills 把重复的工作流打包成可复用的指令**，避免每次都重新解释
- **适合 Skill 的场景**：重复性、步骤固定、可验证
- **Skill 是一个目录 + 一个 SKILL.md 文件**，包含 YAML frontmatter 和 Markdown 指令
- **两种用法**：手动调用（`/skill-name`）或自动触发（Claude 根据 description 判断）
- **两个位置**：personal skills（`~/.claude/skills/`）和 project skills（`.claude/skills/`）
