# 第 2 讲：Agent 可读仓库

> 本讲目标：
> - 把分散在聊天、脑内和外部文档中的关键规则编码进仓库。
> - 用顶层地图与渐进披露降低一次性上下文负担。
> - 用不变量约束边界，而不是微观指定每个实现步骤。
>
> 前置条件：完成一次三行失败诊断 | 上一讲 [<< 01](./01-agent-failure-diagnosis.md) | 下一讲 [03 >>](./03-cross-session-continuity.md)

## Agent 看不见的规则等于不存在

你知道“支付只能走官方回调”“课程不能出现站内 AI”，但这些规则只在聊天记录或团队成员脑中。新会话打开仓库时看不到它们，就会做出局部合理、全局错误的改动。

这一讲把仓库从代码容器变成 Agent 能导航的工作环境。

## 解释

### 先建立记录系统

记录系统是项目事实的权威落点：架构决定、产品边界、执行计划和验证命令都能从仓库中的稳定入口找到。OpenAI 的实践把 `AGENTS.md` 作为短地图，把更长的知识分层放进 `docs/`，并维护架构、计划、质量与可靠性文档。[^S1]

这并不要求把所有内容塞进一个文件。指令文件只回答“先读什么、哪些规则不可违反、如何验证”；顶层地图说明主要目录和职责；具体设计靠链接按需展开。这个由浅入深的读取方式叫渐进披露，Anthropic 将它描述为 Agent 逐步发现相关上下文、只把必要子集留在工作记忆中的策略。[^S3]

```text
AGENTS.md                 # 入口、铁律、验证命令
ARCHITECTURE.md           # 顶层地图与依赖方向
docs/
  product-boundary.md     # 产品范围和明确不做什么
  exec-plans/active.md    # 当前执行计划
  reliability.md          # 失败模式与验收证据
scripts/
  check.sh                # 可运行验证入口
```

### 把知识变成可发现路径

Agent 可读性指 Agent 能在有限上下文中发现与当前任务相关的项目事实。可发现性不是“文件存在”，而是入口文件能指向它、名称能表达用途、命令能验证内容。藏在旧聊天或私人云文档中的隐性知识不会自动进入 Agent 上下文；OpenAI 直接把仓库外的隐性知识视为 Agent 不可见信息。[^S1]

知识债务是项目规则与实现不断变化、仓库说明却没有同步所产生的差距。它的症状包括指令指向已删除命令、架构图与代码方向相反、完成标准只存在于某次对话。处理知识债务的方式不是继续补提示词，而是修正权威文件或自动生成文档。

### 约束结果，不遥控实现

不变量是在所有合法实现中都必须成立的条件，例如“跨边界输入先解析再进入领域逻辑”“公开课程不得调用托管模型”。架构边界说明哪些模块可以依赖哪些模块。OpenAI 的做法是强制这些不变量，而不是规定 Agent 必须使用某个库或逐行怎么写。[^S1]

这样的约束给 Agent 留出实现空间，同时让验证脚本能明确拒绝越界。它比“请写高质量代码”更可执行，也比一份三千行指令文件更容易维护。

## 完整示例

某仓库要求“营销页可以静态发布，但控制台不得进入公开课程站”。较差的写法是把这句话放在一次任务提示中。较好的做法是：在 `AGENTS.md` 写“所有改动先读 `docs/product-boundary.md`”；边界文档列出保留与移除的路由；测试扫描公开路由是否出现 `/console`、`/topup`、`/api/ask`。

这里三层各司其职：入口负责发现，边界文档负责解释，测试负责执行。任何一层变化，都能在仓库里留下可审计差异。

## 轮到你

为下面入口补两个链接和一个不变量：

```markdown
# Agent 入口

- 架构地图：________
- 当前任务：________
- 不变量：公开课程站不得 ________。
```

参考答案可以是 `ARCHITECTURE.md`、`docs/exec-plans/active.md`、不得依赖账户或托管推理。关键是链接指向真实文件，不变量能被检查。

## 练习

### Level 1（热身）

在自己的仓库中列出五条 Agent 完成任务必须知道、但目前不一定能从入口找到的事实。按“已经入库／只在外部／只在脑内”分类。
<!-- rubric -->
- 共列出五条具体事实。
- 每条标出当前权威位置。
- 至少为一条外部或脑内事实选择仓库落点。
<!-- answer -->
常见落点包括 `AGENTS.md`、架构文档、产品边界、执行计划和验证脚本。若一条事实频繁变化，入口应链接到其权威文件，而不是复制多份。
<!-- hint -->
从最近一次你纠正 Agent 的句子开始找。

### Level 2（进阶）

写一个不超过 30 行的 Agent 入口文件，只包含读取顺序、三条不变量和验证命令。
<!-- rubric -->
- 每个链接都指向真实存在的文件。
- 三条不变量都描述结果或边界，不规定具体库。
- 验证命令可在仓库根目录运行，并说明成功信号。
<!-- answer -->
入口应像地图而不是百科全书：先读边界，再读当前计划，最后运行检查。若失败，要求 Agent 复制完整命令、退出码和相关输出，不要只写“检查失败”。
<!-- hint -->
删除所有对当前任务无关的背景段落，再看是否仍能导航。
<!-- /exercises -->

## 总结与下一步

记录系统让事实有落点，渐进披露让事实能按需进入上下文，不变量让边界可执行。下一讲解决另一个断点：新会话如何知道上一会话做到了哪里。
