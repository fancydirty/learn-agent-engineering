# 제4강: 리소스, 스크립트와 실행 경계

> 이번 강의 목표:
> - `references/`, `assets/`, `scripts/`의 용도를 구분합니다.
> - 어떤 자료가 지시문, 참고 자료, 템플릿, 스크립트 중 어디에 속하는지 판단합니다.
> - 실제 Skill 폴더에 리소스 계층화를 한 번 적용합니다. 프로그래밍 능력은 필요하지 않습니다.
>
> 선수 조건: 메타데이터 레이어, 지시 레이어, 리소스 레이어, 온디맨드 로딩을 이해해야 합니다 | 이전 [<< 03](./03-progressive-disclosure.md) | 다음 [05 >>](./05-testing-and-safety.md)

## 리소스 레이어에도 경계가 필요합니다

제3강은 긴 자료를 `SKILL.md`에서 떼어 냈습니다. 그런데 떼어 낸 다음에 새로운 혼란이 나타납니다. 태그 설명, 예시 파일, 빈 템플릿, 검사 명령이 한곳에 섞여 있으면 Agent는 어떤 것이 지식이고, 어떤 것이 복사할 형태이고, 어떤 것이 안정적으로 실행할 수 있는 동작인지 알지 못합니다.

같은 Markdown 파일이라도 Agent가 그것을 어떻게 써야 하는지에 따라 규칙일 수도, 참고 자료일 수도, 출력 템플릿일 수도 있습니다. 여기서 판단할 것은 각 항목의 낙착점입니다. 계속 지시문에 남길지, Agent가 읽게 할지, 복사해서 채우게 할지, 결정론적 스크립트에 맡길지. 이 판단에는 스크립트를 작성하거나 실행할 필요가 없습니다.

## 설명

### `references/`: Agent가 읽는 배경 자료

`references/`는 긴 설명, 용어집, 태그 정의, 리뷰 규칙, 예시 분석을 두기에 적합합니다. 특징은 "읽고 나서 판단한다"는 것입니다. Agent가 이것을 읽는 이유는 작업 기준을 더 잘 이해하기 위해서이지, 한 글자씩 복사하기 위해서가 아닙니다.

인터뷰 노트 Skill에서 `references/tag-guide.md`는 `pain-point`, `workaround`, `buying-signal` 세 태그를 설명하고 각 태그의 판단 예시를 제시할 수 있습니다. 최종 출력 골격을 여기에 담아서는 안 됩니다. 참고 자료의 주된 용도는 설명이기 때문입니다.

### `assets/`: Agent가 재사용하는 형태

`assets/`는 안정적인 출력 형태와 정적 에셋을 두기에 적합합니다. 예를 들어 빈 노트, 설정 템플릿, 이미지, 데이터 표입니다. 텍스트 템플릿을 위해 `templates/` 디렉터리를 따로 만들 필요는 없습니다. `assets/`에 바로 넣고 파일 이름으로 용도를 밝히면 됩니다. 공개 스펙과 OpenAI의 현재 가이드 모두 이 디렉터리 관례를 씁니다.[^S2][^S4]

인터뷰 노트가 매번 요약, 원발언 증거, 주제, 미해결 질문 네 단락을 가져야 한다면, 그 골격을 `assets/note-template.md`에 넣으세요. Agent는 고정 형태가 필요할 때만 그것을 읽고, 사용자 자료로 빈칸을 채웁니다.

### `scripts/`: 결정론적 작업을 위한 자리

`scripts/`는 반복 가능하고, 규칙이 명확하고, 결과를 검사할 수 있는 작업을 두기에 적합합니다. 예를 들어 Markdown에 필수 제목이 있는지 검사하기, CSV를 통일된 필드 이름으로 변환하기, 어떤 디렉터리에 템플릿이 빠졌는지 세기입니다. 공식 자료는 스크립트를 Skill이 조직할 수 있는 구성 요소 중 하나로 꼽으면서, 설치 전에 의존성, 리소스, 외부 네트워크 접근을 감사하라고도 당부합니다.[^S1][^S3]

이 코스는 코드 작성을 요구하지 않습니다. 스크립트가 존재할 가치가 있는지는 세 가지만 보면 됩니다. 규칙이 고정되어 있는가, 손으로 하면 틀리기 쉬운가, 실행 결과를 검사할 수 있는가. 세 답이 모두 명확하면 앞으로 스크립트를 고려할 수 있습니다. 여전히 많은 의미 판단이 필요하다면 지시문이나 참고 자료에 남기세요.

### 결정론적 경계: 스크립트에 맡기면 안 되는 것

결정론적 경계는 "기계가 규칙대로 하는 것"과 "Agent가 의미로 판단하는 것" 사이의 분계선입니다. 스크립트는 제목이 있는지, 파일 이름이 맞는지, 필드가 비었는지 검사하는 데 능하고, Agent는 어떤 고객 원발언이 정말 어떤 결론을 뒷받침하는지 판단하는 데 능합니다.

인터뷰 노트에서 "출력에 `## 原话证据`가 포함되어 있는지 검사한다"는 스크립트가 될 수 있고, "이 원발언이 강한 구매 신호인지 판단한다"는 참고 자료와 Agent 판단의 조합이 더 적합합니다. 의미 판단을 억지로 스크립트에 밀어 넣으면 대개 안정적으로 보이지만 실제로는 경직된 규칙을 얻게 됩니다.

이번 강의 용어:

- `references/`: 긴 배경, 규칙 설명, 판단 기준을 두는 참고 자료 디렉터리.
- `assets/`: 재사용 가능한 템플릿, 이미지, 데이터 파일을 두는 정적 에셋 디렉터리.
- `scripts/`: 규칙이 명확하고, 반복 가능하고, 검사 가능한 결정론적 작업을 두는 스크립트 디렉터리.
- 결정론적 경계: 고정 규칙 실행과 의미 판단을 나누는 경계.

## 완성 예시: 인터뷰 노트 Skill에 네 종류의 내용 배치하기

이 가상의 Skill을 정리하고 있다고 가정해 보겠습니다:

```text
interview-notes/
  SKILL.md
```

손에 여섯 가지 내용이 있습니다:

```text
1. 사용자가 transcript를 주면 중국어 Markdown 노트를 출력한다.
2. 원본 transcript를 수정하지 않고, 고객 원발언을 날조하지 않는다.
3. pain-point, workaround, buying-signal의 태그 설명.
4. 고정된 노트 골격 하나.
5. 가상 transcript 세 편과 그에 대응하는 좋은 노트 예시.
6. 출력에 “摘要、原话证据、开放问题” 세 제목이 있는지 검사한다.
```

먼저 필독 규칙을 배치합니다. 1번과 2번은 실행할 때마다 지켜야 하므로 `SKILL.md` 본문에 남아야 합니다:

```markdown
## Instructions

When the user provides interview transcripts, produce Chinese Markdown notes.
Preserve quoted evidence and do not modify the original transcript.
Do not invent quotes that are not present in the source material.
```

그다음 설명이 필요한 판단 기준을 배치합니다. 3번은 참고 자료에 속합니다:

```text
references/tag-guide.md
```

이 파일의 역할은 Agent가 태그를 판단하도록 돕는 것이지, 최종 노트에 고정 레이아웃을 제공하는 것이 아닙니다.

그다음 재사용 가능한 형태를 배치합니다. 4번은 템플릿에 속합니다:

```text
assets/note-template.md
```

Agent는 사용자가 고정 구조를 요청할 때 그것을 읽고, 실제 내용을 채워 넣습니다.

5번은 `references/examples.md`에 넣을 수 있습니다. 주된 용도가 "무엇이 좋은 노트인가"를 이해하는 것이기 때문입니다. 예시에 개인 정보가 들어 있다면 공개 Skill에 넣을 수 없습니다. 여기서는 반드시 공개 자료나 가상 자료를 써야 합니다.

6번이 비로소 스크립트 경계에 가깝습니다. 규칙이 고정되어 있고, 수동 검사로는 놓치기 쉽고, 결과가 "어느 제목이 빠졌는지"를 명확히 돌려줄 수 있습니다. 앞으로 여기에 둘 수 있습니다:

```text
scripts/check-note-headings.js
```

하지만 프로그래밍을 하지 못한다면 먼저 `references/quality-check.md`의 체크리스트로 써 두어도 좋습니다. 중요한 것은 근거 없이 위험한 스크립트를 만들지 않는 것, 스크립트가 사용자 파일을 수정하게 하지 않는 것입니다. 먼저 경계를 분명히 하세요.

최종 구조:

```text
interview-notes/
  SKILL.md
  references/
    tag-guide.md
    examples.md
    quality-check.md
  assets/
    note-template.md
  scripts/
    check-note-headings.js
```

여기의 `scripts/`는 앞으로의 자리이지, 이번 강의가 지금 당장 구현하라고 요구하는 코드가 아닙니다. 왜 그것이 의미 판단이 아니라 결정론적 검사에 속하는지 설명할 수 있으면 됩니다.

## 반쯤 완성된 예시: 내용을 올바른 위치에 놓기

아래는 릴리스 노트 Skill의 리소스 목록입니다. 각 항목을 `SKILL.md`, `references/`, `assets/`, `scripts/` 중 하나에 배치하세요.

```text
A. PR 요약을 입력하면 사용자용 Markdown 릴리스 노트를 출력한다.
B. Git tag를 만들지 않고 배포를 실행하지 않는다.
C. “breaking change”, “known issue”, “migration note”의 판단 설명.
D. 릴리스 노트의 고정 구조: 신규 기능, 수정 사항, 알려진 문제.
E. Markdown에 2단계 제목 “Added”와 “Fixed”가 있는지 검사한다.
```

완성할 부분:

```text
`SKILL.md`: ________________________________
`references/`: ________________________________
`assets/`: ________________________________
`scripts/`: ________________________________
```

참고 답안:

```text
`SKILL.md`: A, B. 매 작업마다 지켜야 하는 핵심 지시와 경계입니다.
`references/`: C. 판단 기준을 설명하며, Agent가 읽고 이해해야 합니다.
`assets/`: D. 재사용 가능한 출력 골격이므로 복사한 뒤 채우기에 적합합니다.
`scripts/`: E. 고정된 제목 검사이며 결과를 명확히 판정할 수 있습니다.
```

C를 스크립트에 넣으면 의미 판단이 경직된 키워드 매칭으로 바뀝니다. D를 길게 `SKILL.md`에 쓰면 진입점이 무거워집니다.

## 연습 문제

### Level 1 (워밍업)

이미 써 본 Skill 초안 하나를 골라 내용 8개를 나열하고, `SKILL.md`, `references/`, `assets/`, `scripts/` 네 종류로 나누세요. 실제로 스크립트를 쓸 필요는 없고, 어떤 내용이 앞으로 스크립트화될 수 있는지만 설명하면 됩니다.

방법: Skill 초안이나 brief를 열고 규칙, 예시, 템플릿, 검사 항목을 한 줄씩 따로 떼어 냅니다. 각 항목 뒤에 "매번 필독", "읽고 판단", "복사 후 채우기", "고정 검사" 중 하나를 표시하세요.
<!-- rubric -->
- 최소 8개 항목을 나열했습니다.
- 네 종류 중 최소 세 종류에 내용이 있습니다. 어느 종류가 비었다면 그 이유를 한 문장으로 씁니다.
- 각 항목에 한 문장짜리 배치 이유가 있습니다.
- 스크립트화에 적합하지 않은 의미 판단을 최소 하나 짚었습니다.
<!-- answer -->
합격 답안은 "입출력과 처리하지 않음 경계"를 `SKILL.md`에, "용어 설명과 좋고 나쁜 예시"를 `references/`에, "고정된 보고 골격"을 `assets/`에 넣고, "제목이 있는지, 필드가 비었는지" 같은 고정 검사를 앞으로의 `scripts/` 후보로 나열합니다. 흔한 실수는 "내용에 통찰이 있는지 판단하기"를 스크립트로 분류하는 것입니다. 그것은 의미에 너무 의존하므로 참고 기준과 Agent 판단으로 돌려보내야 합니다.
<!-- hint -->
먼저 디렉터리 이름은 생각하지 말고, 각 항목에 네 라벨 중 하나만 붙여 보세요.
<!-- hint -->
어떤 문장에 "정말 결론을 뒷받침하는지 판단"이 들어 있다면, 그것은 대개 결정론적 스크립트가 아닙니다.

### Level 2 (심화)

실제 연습용 Skill 폴더에서 리소스 계층화를 한 번 수행하세요. 빈 파일이나 초안 파일만 만들어도 되지만, 읽을 수 있는 디렉터리가 되어야 합니다. `SKILL.md`에 리소스 파일 두 개 이상을 더한 형태입니다. 개인 데이터를 넣지 말고, 파일을 수정하거나 삭제하는 스크립트도 쓰지 마세요.

방법: IDE나 터미널에서 연습용 Skill 폴더를 엽니다. `SKILL.md` 본문을 핵심 지시와 리소스 안내로 줄이고, `references/` 파일 하나와 `assets/` 파일 하나를 새로 만듭니다. 어떤 항목이 앞으로 스크립트에 적합하다고 생각하면 `scripts/README.md`만 만들어 검사 목표를 적고, 실행 가능한 코드는 쓰지 마세요.
<!-- rubric -->
- 디렉터리에 최소한 `SKILL.md`, `references/` 파일 하나, `assets/` 파일 하나가 있습니다.
- `SKILL.md` 본문에 리소스 안내가 있고, 긴 참고 자료가 욱여넣어져 있지 않습니다.
- 리소스 파일 이름과 내용 제목이 용도를 설명합니다.
- 실제 개인 자료가 없고, 위험한 스크립트가 없고, 사용자 파일을 자동으로 수정하는 명령이 없습니다.
<!-- answer -->
합격 디렉터리의 한 예: `SKILL.md`, `references/tag-guide.md`, `assets/note-template.md`, `scripts/README.md`. `SKILL.md`에는 "태그 정의가 필요하면 `references/tag-guide.md`를 읽고, 고정 출력 구조가 필요하면 `assets/note-template.md`를 읽는다"고 씁니다. `scripts/README.md`에는 "앞으로 필수 제목의 존재 여부를 검사할 수 있다"만 기록합니다. 실행 가능한 스크립트가 아직 없어도 리소스 계층화는 이미 완료된 것입니다.
<!-- hint -->
실제 폴더에는 먼저 아주 짧은 자리표시 내용, 예를 들어 제목 하나와 설명 두 줄만 써도 됩니다.
<!-- hint -->
스크립트를 쓰고 싶어지면 먼저 검사 목표 한 문장으로 바꿔 쓰세요. 이번 강의는 경계가 분명하기만 하면 됩니다.

## 가져갈 것: 각자 자리를 찾은 계층 지도

리소스 계층화가 끝나면 진입 규칙, 참고 자료, 출력 형태, 고정 검사가 각자의 자리를 갖습니다. 다음 강의는 이 계층 지도를 실제 작업에 되돌려 놓고, Skill이 써야 할 때 나타나는지, 넘겨받으면 안 될 때 멈추는지, 그리고 딸려 오는 파일이 위험을 가져오지는 않는지 검사합니다.
